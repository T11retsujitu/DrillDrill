# セクション 03 — ヒストグラムとビット深度

## 1. 学習目標
- ヒストグラム（度数分布）を自作し、画像の輝度分布を読めるようになる。
- 8bit / 16bit / 浮動小数点の違いと、**表示のためのスケーリング**を理解する。
- 線形コントラスト伸長（min-max ストレッチ）を実装し、**何が変わり何が変わらないか**を説明できる。
- STL コンテナ（`std::vector`）を C++ の関数戻り値として自然に使える。

## 2. 前提知識
- セクション 01（画素アクセス・飽和）。

## 3. 推定所要時間
- 約 4 時間。

## 4. 最小限の理論
- **ヒストグラム**: `hist[v]` = 画素値 v の画素数。画像の「明るさの内訳」。コントラストが低い
  画像はヒストグラムが狭い範囲に固まる。
- **ビット深度**: 8bit は 256 階調、16bit は 65536 階調。CD-SEM 実機は 8bit 出力が多いが、
  処理途中は 16bit や float を使うことがある。**PNG は 8bit も 16bit も保存できる**が、
  画面表示は事実上 8bit なので、16bit 画像は表示のたびに「どの範囲を 0..255 に割り当てるか」
  を決める必要がある（＝スケーリング）。
- **線形コントラスト伸長**: `dst = (src - min) * 255 / (max - min)`。
  分布を広げるだけで**情報は増えない**（ヒストグラムに「歯抜け」ができる）。
  逆に 16bit→8bit の変換は**階調を捨てる**（不可逆）。

## 5. 動作を予測する問題
- 全画素が同じ値（例: 77）の画像に min-max ストレッチをかけると何が起きるべきか？
  素朴に式を適用すると何で割ることになる？
- 16bit 値 `32768` を `[0,65535] → [0,255]` で変換すると何になる？
- コントラスト伸長した画像のヒストグラムには、伸長前と比べてどんな特徴が現れる？

## 6. 実装課題
`src/histogram.cpp` の 3 関数を実装する（仕様は `include/histogram.hpp`）。

1. `compute_histogram(src)` — 256 ビンの度数分布。総和が画素数になること。
2. `rescale_to_8u(src, in_min, in_max)` — 任意深度の 1ch 画像を `[in_min,in_max]→[0,255]` の
   線形写像で CV_8U 化。区間外は飽和。ヒント: まず `convertTo` で double 化すると
   どの深度でも同じループで書ける。
3. `stretch_contrast(src)` — 8bit の min-max ストレッチ。`cv::minMaxLoc` で最小・最大を求め、
   `rescale_to_8u` を**再利用**する。一様画像は `clone` を返す（ゼロ除算を避ける）。

## 9. 結果の観察
- `sec03_hist.png`（伸長前）と `sec03_hist_stretched.png`（伸長後）を見比べる。
  伸長後の「歯抜け（櫛状）」が確認できるはず。
- `sec03_16bit_view_fullrange.png` と `sec03_16bit_view_fitrange.png` の見え方の違いを確認する。
  同じデータでも**スケーリング次第で見え方が全く変わる**ことを体感する。
- `sec03_hist.csv` を表計算ソフトや Python でプロットしてもよい。

## 10. OpenCV 実装との比較
- `compute_histogram` ↔ `cv::calcHist`。使い方の複雑さと汎用性のトレードオフを見る。
- `stretch_contrast` ↔ `cv::normalize(src, dst, 0, 255, cv::NORM_MINMAX)` + `convertTo(CV_8U)`。
  自作と結果を比較し、**丸めで 1 だけ違う画素**が出るか調べてみる（出たら理由を考える）。

## 11. 考察問題
- コントラスト伸長で「見やすくなった」画像は、情報が増えたのか？ ヒストグラムの歯抜けは
  何を意味するか？
- ノイズの多い画像を伸長すると、ノイズはどうなるか？
- 16bit の CD-SEM 画像を 8bit に落として処理してよいのはどんな場面か？
  逆にダメなのはどんな場面か（微小な輝度差に情報がある場合を考える）。

## 12. 発展課題
- ヒストグラム等化（`cv::equalizeHist`）を調べ、min-max ストレッチとの違いを実画像で比較する。
- パーセンタイル・ストレッチ（例: 1%〜99% を 0..255 に割り当て、外れ値を無視する）を
  `compute_histogram` の結果を使って実装してみる。
