# セクション 05 — 平滑化フィルタ（box・ガウシアン）

## 1. 学習目標
- box（平均化）カーネルとガウシアンカーネルを自作し、`convolve` と組み合わせて平滑化できる。
- 「カーネルの総和 = 1」の意味（明るさ保存）を説明できる。
- sigma・カーネルサイズとぼけの強さの関係を説明できる。
- **ノイズ低減とエッジ保存のトレードオフ**を、画像と数値の両方で確認できる。

## 2. 前提知識
- **セクション 04 の `convolve` が完成していること**（このセクションはそれを土台に使う。
  未完成だとビルドは通ってもテストが失敗する）。

## 3. 推定所要時間
- 約 4 時間。

## 4. 最小限の理論
- **box フィルタ**: 近傍の単純平均。実装は最も簡単だが、方向によってぼけ方が均一でなく、
  エッジが階段状になまりやすい。
- **ガウシアンフィルタ**: 中心ほど重い重み `exp(-r²/2σ²)`。滑らかで等方的なぼけ。
  `sigma` が実質の強さで、カーネルサイズは「裾をどこで打ち切るか」。目安は **ksize ≈ 6σ**
  （それ以上大きくしてもほぼ変わらない）。
- **総和 1 の正規化**: 重みの合計が 1 でないと、一様な領域の明るさが変わってしまう。
  「一様画像を入れたら一様画像が出る」は平滑化フィルタの基本チェック。
- ノイズ（ランダム変動）は平均化で分散が減る。しかしエッジ（急な変化）も「平均」に
  巻き込まれてなまる。**ノイズだけを選んで消す方法はこの段階では存在しない**。

## 5. 動作を予測する問題
- 一様な画像（全画素 100）に 3x3 box をかけると出力は？ 総和が 1 でないカーネルなら？
- 5x5 box と、sigma=1 の 5x5 ガウシアンでは、どちらがエッジをより強くなますか？
- sigma を 2 倍にすると、ノイズと線幅（CD）計測はそれぞれどうなると予想するか？

## 6. 実装課題
`src/smoothing.cpp` の 4 関数を実装する（仕様は `include/smoothing.hpp`）。

1. `make_box_kernel(ksize)` — 全要素 `1/(ksize*ksize)` の CV_32F。
2. `make_gaussian_kernel(ksize, sigma)` — 中心からの距離で `exp` 重み、**総和 1 に正規化**。
3. `box_blur(src, ksize)` / `gaussian_blur(src, ksize, sigma)` — カーネルを作って
   セクション 04 の `convolve` を呼ぶだけ（再利用の練習）。

## 9. 結果の観察
- `sec05_noisy.png` → `sec05_gauss5.png` → `sec05_gauss9.png` の順に、ノイズの減りと
  **ラインの縁のなまり**を拡大して見比べる。
- デモの PSNR 表で「最も PSNR が高い設定」を確認する。その設定の画像のエッジは
  本当に「一番良い」か？ PSNR と見た目の印象がずれる例を探す。

## 10. OpenCV 実装との比較
- `box_blur` ↔ `cv::filter2D`(box カーネル) / `cv::blur`、`gaussian_blur` ↔ `cv::GaussianBlur`
  （いずれも `BORDER_REPLICATE` 指定）。どちらもテストで数値一致を確認する。実行時間は大差がつく。
- `cv::getGaussianKernel(ksize, sigma)` は **1 次元**カーネルを返す。なぜ 1 次元でよいのか
  （分離可能性）を調べる。

## 11. 考察問題
- ガウシアンの「総和 1」を忘れるとどんな画像になるか（実験して確認してよい）。
- PSNR が上がっているのに CD 計測には悪影響がありうるのはなぜか。
  エッジの傾き（ラインプロファイルの肩）は平滑化でどう変わるか。
- CD-SEM のショットノイズ（画素ごとに独立）に対して、平均化が効く理由を
  「分散」という言葉を使って説明せよ。

## 12. 発展課題
- **分離可能ガウシアン**: 1 次元カーネルを横→縦の 2 回適用する実装に変え、
  2 次元版と結果が一致すること・実行時間が O(k²)→O(2k) に減ることを確認する。
- ksize を 6σ より小さく打ち切ったとき、`cv::GaussianBlur` との差がどう増えるか測る。
