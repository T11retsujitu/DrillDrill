# セクション 04 — 畳み込みエンジン

このセクションの `convolve` は、以降のセクション（平滑化・微分フィルタ）の**土台**になります。
ここで境界処理と型の扱いを固めておくと、後がすべて楽になります。

## 1. 学習目標
- 畳み込み（相関）の計算を、境界処理込みで自作できる。
- 相関（correlation）と数学的な畳み込み（convolution）の違いを説明できる。
- 境界処理（replicate）の必要性と選択肢を説明できる。
- 自作実装と `cv::filter2D` の一致を**数値で**確認できる。

## 2. 前提知識
- セクション 03（型変換・スケーリング）。

## 3. 推定所要時間
- 約 5 時間。

## 4. 最小限の理論
- **相関**: 出力の各画素は「カーネルを重ねた近傍の重み付き和」。
  `out(y,x) = Σ_{j,i} kernel(j,i) * src(y+j-kr, x+i-kc)`（kr,kc はカーネル中心）。
- **畳み込みとの違い**: 数学的な畳み込みはカーネルを 180° 回転してから相関を取る。
  `cv::filter2D` も実は**相関**を計算する。対称カーネル（box, ガウシアン）では区別が消えるが、
  非対称カーネル（微分系）では符号や向きが変わるので、**どちらの定義かを常に意識する**。
- **境界処理**: 画像端ではカーネルがはみ出す。はみ出した分をどう埋めるかで結果が変わる。
  本ドリルでは「最も近い画素を複製する」**replicate** を採用する（`BORDER_REPLICATE`）。
  他に reflect（鏡映）、constant（定数）などがある。
- **出力型**: 重み付き和は負にも 255 超にもなるので、出力は **CV_32F** にする。
  8bit に戻すのは表示・保存の直前だけ（セクション 03 の教訓）。
- 計算量は O(W·H·k²)。カーネルが大きいほど急激に遅くなる。

## 5. 動作を予測する問題
- 3x3 の恒等カーネル（中心だけ 1）を適用すると出力はどうなる？
- カーネル `(0,1)` の位置だけ 1（中心の 1 行**上**）だと、画像はどちらに動く？
- `src=[10,20,30]` に `[0.25, 0.5, 0.25]` を replicate 境界で適用したとき、
  両端の出力値を手計算せよ（テストと同じ値になる）。

## 6. 実装課題
`src/convolve.cpp` の `convolve(src, kernel)` を実装する（仕様は `include/convolve.hpp`）。

- src は CV_8U/CV_32F の 1ch、kernel は CV_32F の奇数サイズ。出力は CV_32F。
- 境界は replicate（座標を `std::clamp(v, 0, n-1)` で丸めるのが簡単）。
- src は変更しない。
- 4 重ループ（y, x, j, i）の素朴な実装でよい。まず**正しく**、速さはその後。

## 10. OpenCV 実装との比較
- 結果は `cv::filter2D(..., BORDER_REPLICATE)` と最大絶対差 ~1e-3 で一致するはず。
- 実行時間は大きく差がつく（数十倍〜）。なぜ OpenCV は速いのか調べる:
  分離可能カーネル・SIMD・マルチスレッド・キャッシュ最適化。

## 11. 考察問題

  画像端にあるラインの **CD 計測**にはどちらが有利か？
- 出力を CV_32F ではなく CV_8U にすると、微分系カーネル（負の値が出る）で何が失われるか？
- filter2D が「相関」であることを、非対称カーネルでどう確認できるか？

## 12. 発展課題
- `.at` を使った実装と `.ptr` を使った実装で実行時間を比較する。
- reflect 境界（`BORDER_REFLECT_101`）をオプション引数で追加し、filter2D と照合する。
- k×k カーネルの実行時間を k=3,5,9,15 で測り、O(k²) を実測で確認する。
